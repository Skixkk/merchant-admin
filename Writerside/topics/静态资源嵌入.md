# 静态资源嵌入

误区：**VitePress 并非完全不支持 png/pdf/docx 等格式，只是「不支持将这些格式直接作为文档页面的入口文件」，作为静态资源嵌入、下载链接使用是完全支持的
**。

---

## 一、VitePress 官方明确的格式支持边界

### 【核心支持：页面内容入口文件】

只有两种格式可以作为独立的文档页面，放在 `docs` 目录下自动生成路由、被VitePress编译：

- `.md`（Markdown，官方核心推荐格式）
- `.html`（原生HTML，可直接作为独立页面）

规则示例：`docs/guide.md` 会自动生成路由 `/guide/`，`docs/api.html` 会生成 `/api.html`。

### 【完全支持：静态资源文件】

以下格式**不能作为页面入口，但可以正常在文档中嵌入、引用、提供下载**，100%兼容构建和部署：

- 图片类：`png`、`jpg`、`jpeg`、`gif`、`svg`、`webp` 等所有主流图片格式
- 文档类：`pdf`、`docx`、`doc`、`xlsx`、`zip` 等所有文件格式

规则：这类文件需要放在 `docs/public/` 目录下，然后在 md/html 中引用。

---

## 二、为什么不支持 docx/doc/pdf 作为页面入口？

1. **核心定位限制**：VitePress 是静态站点生成器(SSG)，核心是把纯文本的 md/html 编译成静态HTML页面；而 docx/doc
   是二进制富文本格式、pdf 是固定布局的二进制格式，无法被 VitePress 的 Markdown/Vue 编译器解析，也无法生成对应的路由和页面结构。
2. **渲染逻辑限制**：VitePress 基于 Vite 和 Vue3，只能处理能被编译成 Vue 组件/原生HTML的内容，二进制文档格式无法被直接渲染成网页。
3. **工程化限制**：二进制格式无法做 Git 版本对比（diff），不符合技术文档轻量化、可协作的最佳实践。

---

## 三、各格式的完美兼容方案（可直接落地）

### 1. png/jpg 等图片：正常嵌入使用

① 把图片文件放到 `docs/public/images/` 目录下（没有就新建）
② 在 md 文件中直接引用：

```markdown
![图片说明](/images/你的图片名.png)
```

③ 也可以用 HTML 自定义宽高：

```html
<img src="/images/你的图片名.png" alt="图片说明" width="800"/>
```

### 2. pdf 文件：在线预览+下载

#### 方案1：提供下载链接（推荐，兼容性最好）

① 把 pdf 放到 `docs/public/files/` 目录下
② md 中引用：

```markdown
[点击下载完整文档](/files/你的文档.pdf)
```

#### 在线嵌入预览

```html

<iframe src="/files/你的文档.pdf" width="100%" height="600px" frameborder="0"></iframe>
```

### 3. docx/doc 文件：两种方案

#### 方案1：转为 Markdown（推荐，最佳体验）

用工具把 docx/doc 转成 md 格式，直接作为 VitePress 的页面，完美兼容所有功能：

- 在线工具：Zamzar、CloudConvert
- 本地工具：Pandoc、Typora（直接导入docx导出md）

#### 方案2：提供下载链接

① 把 docx 放到 `docs/public/files/` 目录下
② md 中引用：

```markdown
[点击下载Word文档](/files/你的文档.docx)
```

---

## 四、补充关键注意事项

1. `public` 目录规则：放在 `docs/public/` 下的文件，会被原封不动复制到构建后的 `dist` 根目录，所以引用路径**直接以 `/` 开头
   **，不需要加 `/public/`。
2. 构建兼容性：以上所有方案，在 `npm run docs:build` 构建后都会正常生效，不会出现路径错误。
3. 大文件建议：超过10MB的pdf/压缩包，建议不要放在Git仓库里，改用云盘外链，避免仓库体积过大。
