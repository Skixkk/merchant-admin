# CSR 永远只有 1 个 index.html 壳子

我明白你的核心疑问了！我给你**最精准、最肯定**的回答：

> ✅ **这个配置 100% 不会影响 SSG/SSR 的核心功能！**

## 一句话总结

你写的这段 `build/rolldown` 配置**只负责拆分「客户端的 JS/CSS 文件」**
**完全不影响：**

- SSG 生成多少个 HTML 文件
- SSR 服务端渲染的 HTML 内容
- SSR 生成的服务端运行代码
- CSR 的单页架构

# 分场景给你讲清楚（你最关心的3点）

## 1. 对 **SSG（静态生成）**

✅ **不影响生成 HTML 的数量、结构、内容**

- 你配置前：生成 `index.html`、`about.html`、`news.html`
- 你配置后：**还是生成完全一样的 HTML 文件**
- 唯一变化：HTML 里引用的 JS 从 1 个大文件 → 拆成多个小文件
- **HTML 本身一点都不变！**

## 2. 对 **SSR（服务端渲染）**

✅ **不影响服务端逻辑、不影响服务端渲染的 HTML**

- SSR 服务端运行的代码（`.output/server`）**完全不受这个配置影响**
- 服务端吐出的 HTML 结构、内容**完全不变**
- 只优化用户浏览器加载的**客户端JS**
- **服务端功能 100% 正常**

## 3. 对 **CSR（客户端渲染）**

✅ **不会改变「单HTML + 多JS」的架构**

- CSR 永远只有 1 个 `index.html` 壳子
- 这个配置只是把**1个大JS拆成多个小JS**
- **架构不变，还是纯 CSR**
